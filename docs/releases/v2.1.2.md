# Infra Sentinel 2.1.2

本次新增本地诊断历史和可选 SSD 健康信息，并修复模型提示与时间范围不一致的问题。

## 更新内容

- 用量总览、模型分析和等价价值视图中的疑似灰度、试用、免费版与本体估算提示，只显示该来源在所选时段内实际有用量的模型。选择“全部”时保留累计历史；提示数量是模型数，不是请求数。
- 诊断历史记录已有观测中的异常、严重级别变化和明确恢复，支持按类别与时间筛选，并在重启后保留。缺失、过期或停用的来源不会被视为已恢复。
- 桌面和只读命令行查询共用同一份诊断记录。历史从首次启用后开始，保留上限为 30 天或 10,000 条事件；不回放旧日志。
- 系统页可通过已安装且可读取的 `smartctl` 补充支持的 NVMe SSD 健康、寿命使用比例、温度及累计读写等信息。不会安装工具、请求提权或影响原生健康检测；无法读取时保持缺失。
- 活动日历保留每天的完整模型构成，包括未进入全部历史主要模型排名的模型。

诊断记录不包含提示词、响应正文、凭据或原始错误内容，也不改变 Token 与网络用量统计。

## Changes

- Scope rollout, trial, free-tier, and base-estimate annotations to each provider's
  actual usage in the selected range across overview, model, and equivalent-value
  views. All history retains cumulative coverage; badge counts mean models, not requests.
- Add local diagnostic history for existing observations, severity changes, and
  confirmed recoveries, with category/time filters and persistence across restarts.
  Missing, stale, and disabled observations cannot confirm recovery.
- Share the journal between the desktop and read-only CLI queries. Recording begins
  when enabled; retention is bounded to 30 days or 10,000 events without replaying old logs.
- Add optional NVMe SMART health, wear, temperature, and lifetime counters through
  an already installed, readable `smartctl`. No tool installation or privilege
  escalation is performed, and native health checks remain available.
- Keep each calendar day's model breakdown, including models outside the leading
  models across all recorded history.

Diagnostic records exclude prompts, response bodies, credentials, and raw errors.
Token and network usage accounting are unchanged.
