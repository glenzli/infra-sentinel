# Codex 本机请求遥测

Infra Sentinel 可选接收 Codex 的本机 OTLP/HTTP JSON 日志，显示按精确模型
保留的最近一次**估算流速**和**首 Token 延迟**。用量总览、模型分析与
Agent 活动详情均不再显示“轮次平均”或“请求平均”；等待单独用延迟表达。
样本可来自其他本机 Codex 对话或子 Agent。

估算流速 = 同一次请求的输出 Token ÷（请求耗时 − 首 Token 延迟）。
例如本机 83 Token / 10.287 秒、首 Token 延迟 8.940 秒的样本，界面显示
估算流速 61.6 Token/s、首 Token 延迟 8.94 秒。两者携带相同模型与样本
时间。不能拿另一轮次或请求的延迟配这个流速。若没有可靠流速，只显示
有效的首输出延迟，不以平均速度补位；缺失延迟不显示为零。

估算输出含推理，计数与流起止未逐 Token 对齐，缓冲可能放大结果，故明确
标为“估算”，不冒充实测客户端流速或服务端解码速度。首 Token 延迟缺失、
非正数、超过请求耗时，或剩余时间不足 250 ms、输出不足两个 Token 时
不显示估算。250 ms 是避免短时间窗口放大计时误差的保守展示阈值；
不会将异常速度裁剪成一个看似合理的值。若已有实测流式耗时，则优先使用
实测流速。估算只由现有数值派生，不增加遥测采集，不改变数值缓存结构或
写入频率；派生指标会随既有界面恢复快照保存。

## 启用与撤销

先退出旧版 Infra Sentinel，构建并启动当前版本，然后显式启用：

```sh
PYTHONPATH=src python3 -m infra_sentinel.cli.codex_telemetry enable
```

打包 Agent 也提供同一入口：`infra-agent --codex-telemetry enable`。
这是显式运行一次的自动配置命令：备份用户配置、生成本机认证凭据并写入
受管理的 OTLP 块。启用后，Sentinel 每次启动都会自动开启接收服务。
安装和普通启动不修改 Codex 配置，当前设置页尚无启用开关；macOS 回环
代理例外仍需按下一节单独配置，命令不会改 shell 启动文件或自动重启 Codex。
两种入口默认使用桌面应用的数据目录；自定义运行时可指定 `--state-dir`，
打包入口则可用 `--config` 选择配置旁的状态目录。环境变量
`INFRA_SENTINEL_STATE_DIR` 的优先级与桌面应用一致。
配置后重启 Infra Sentinel，确保接收服务启动；已有 Codex 进程可能需要重启
才会应用导出配置。状态查询与撤销分别为 `status`、`disable`。

默认只监听 `127.0.0.1:43182/v1/logs`，使用随机 Bearer 凭据。
配置工具在用户级 Codex `config.toml` 中增加有起止标记的独立块，保留其他
用户设置，首次启用前创建私有备份。文件以 `0600` 权限写入。
已有第三方遥测配置或被手动修改的管理块会阻止自动覆盖。
撤销只删除受管理块；重新启动两个应用后停止导出和监听。

## macOS 系统代理与回环直连

系统代理的绕过列表包含 `localhost`、`127.0.0.1`，并不保证每个 HTTP
客户端都会遵守。2026-10-29 检查桌面内置 Codex 的二进制，确认其使用
`reqwest 0.12.28` / `hyper-util 0.1.20`。这一版 macOS 系统代理适配器
读取 HTTP/HTTPS 代理地址，没有读取系统绕过列表；回环例外需另由进程的
`NO_PROXY` / `no_proxy` 提供。接收器认证直连返回 200，而 Codex 上报
返回 502 时，应检查该路径，不能仅凭“已重启”判断遥测接入成功。

本机修复在登录 shell 配置 `~/.zprofile` 中使用独立管理块，仅在
`CODEX_SHELL=1` 时合并现有大小写两种例外列表，并补充 `127.0.0.1`、
`localhost`；重复加载不会继续追加相同内容，原文件先保存私有备份。
当前桌面版本在读取登录 shell 环境时设置该标记，并将结果传给后台；
这个限定依赖已核对的桌面启动行为，升级后需重新验证。普通终端启动不
执行该管理块，系统代理配置、HTTP/HTTPS 代理及已有例外均保留。

`NO_PROXY` 按目标地址作用于整个 Codex 进程，并非导出器专用开关，也不
支持将此处规则限定到遥测端口。远端模型地址仍使用原代理；如果另配了
本机模型网关，也会命中本机例外，需先确认该范围符合预期。本机已检查
没有自定义模型网关，并用同版本代理库确认远端 OpenAI 地址的代理选择
在修复前后保持一致。不能以清空 HTTP/HTTPS 代理或 `NO_PROXY=*` 替代。

已运行的后台不会自动得到新的进程环境。需完整退出并重新打开 Codex，
完成新的模型请求后，核对“已配对请求”计数与样本时间确实更新。
独立 CLI 验证只证明新启动进程的路径；桌面持续采集必须另外验收，不能
将历史探针样本或 rollout 用量更新当作新遥测已经送达的证据。

本机修复后的独立真实 Astra 请求于 2026-10-29 16:30:30（新加坡时间）
产生 163 个输出 Token，请求耗时 7.803 秒、首 Token 延迟 4.717 秒，
估算流速约 52.8 Token/s。生产接收器已将该新样本保存，数值缓存从
175 字节增至 327 字节，Codex 用量报告的输出计数也为 163；未保存原始
遥测或回答。该结果验收了修复后的启动环境与生产接收路径，桌面后台
是否持续导出仍须按上一段另行确认。

撤销这一额外环境修复时，仅移除登录 shell 配置中以
`Infra Sentinel Codex local telemetry proxy bypass` 标识的管理块，并
重新启动 Codex；不要用旧备份覆盖修复后新增的其他用户配置。

## 已验证字段与配对限制

2026-10-29，使用桌面应用内置的 Codex `0.165.0-alpha.1.2`，独立临时
进程、临时用户级配置档、既有认证和受控模型请求完成实测：

- `codex.websocket_request`：精确模型、会话标识、事件时间、成功状态、发送耗时。
- `codex.sse_event` / `response.completed`：精确模型、会话标识、事件时间、
  输出 Token、推理 Token、`ttft_ms`。首 Token 延迟直接使用上游值，
  相减后的速度仅作显式估算，不声称纯生成速度。
- 一次受控两秒工具等待的样本有两次模型请求：56 Token / 2.410 秒、
  83 Token / 1.630 秒；两次请求间约 2.132 秒的工具间隔没有进入请求耗时。
- 同一样本仅日志导出为 124,320 字节 / 33 条记录。全量 trace 验证的另一
  短请求为约 1.7 MB / 672 条记录，因此正式配置只启用日志，关闭 trace。

当前导出日志没有可直接使用的逐请求 response ID。配对严格限定为同会话、
同模型、单一在途请求，要求成功发送与完成事件顺序一致。零输出预热、失败、
缺失、重叠、乱序、非法数值均不用于生成速度。HTTP 回退若缺少同等发送
信号，保留已有轮次平均，不猜测请求速度。不同客户端版本需实际验证信号。
这次实测不代表已经运行的桌面进程会动态重载配置。

## 隐私与资源边界

- 不提取、不记录 OTLP resource 属性、账户、邮箱、主机、路径、提示词、
  回答、工具参数与工具输出；这些字段可能到达本机接收器，但被立即丢弃。
- 会话标识进入共享内存前用私有随机密钥作 HMAC；配对状态仅在内存中，
  不持久化原始标识、摘要或遥测正文。
- 独立 checkpoint 仅含至多 64 个模型的最近有效数值样本，保留最多 7 天。
  过期样本在应用运行时的下一次采样清除，应用关闭期间在下次启动后清除。
  只在采样周期有新样本时写入，不逐请求或逐流事件写盘。
- 遥测绝不更新 Token 用量账本、费用或历史指标；关闭、丢包或接收失败不
  影响既有 rollout 用量采集。缺失保持缺失，不显示为零速度。
- 单个请求和解压后正文均限制 1 MiB，单批至多 512 条记录；至多两个
  HTTP 工作线程、256 个会话/模型流、4,096 个去重标记，接收速率限制
  4 MiB/s。连接有超时，不设置无界队列。过载拒绝并保留诊断计数。
- 仅接受精确回环 Host、有效认证和 JSON OTLP 日志；拒绝浏览器 Origin、
  分块传输、重复长度/认证头及其他路径。原始请求及错误正文不进入日志。

导出侧仍有序列化和发送成本。接收端过滤不能消除 Codex 的这部分成本。
配置只开放本机端点；代理环境下应确保回环流量走本机直接连接。

## 本机验证结果

生产接收器的受控实包验证收到两次有效模型请求：49 Token / 2.050 秒、
83 Token / 1.306 秒；合计 132 Token，与 Codex 的整轮报告一致。
该轮仅日志遥测为 121,510 字节，配对没有丢失或拒绝，不包含工具间隔。
复现入口为 `scripts/probe_codex_telemetry.py --codex <待验证的 Codex 可执行文件>`；
它会产生一个真实、临时模型请求，报告只包含经过过滤的数值，结束后删除
测试配置档，不改用户主配置。

500 个合成批次（合计 988,120 字节）的生产 HTTP 接收路径测得：

| 项目 | 本机结果 |
| --- | ---: |
| 成功批次 | 500 / 500 |
| 平均回环往返 | 0.917 ms |
| P95 回环往返 | 1.124 ms |
| 客户端与接收器合计 CPU | 0.544 s |
| Python 内存跟踪峰值 | 685,047 bytes |
| 收包阶段产生的文件 | 0 |
| 最后一次 64 模型样本 checkpoint | 8,782 bytes |

这是带内存跟踪的本机合成压力测试，CPU 包括测试发送端，不等于 Codex
进程的端到端性能损耗，也不是进程 RSS 上限。实际开销会随请求量和版本变化。
接收器初次接入的完整 Python 回归共 424 项，412 项通过、12 项因目标平台
或可选条件跳过；21 项原生壳测试通过。本次估算流速调整另有 73 项性能、
遥测、用量和 Projection 回归通过，前端构建及中英文来源/模型视图检查通过。
性能展示精简另经 `ui/scripts/check-ai-performance.mjs` 验证中英文、四种时间
范围、来源/模型/价值/活动视图、同请求配对及缺失数据行为，并在重启后的
桌面窗口确认只显示估算流速 61.6 Token/s 与同样本首 Token 延迟 8.94 秒。
